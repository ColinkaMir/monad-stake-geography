    Methodology

    How this map is built, and what it deliberately omits.

    • Stake = on-chain stake snapshot at the epoch shown, used to weight every aggregate.
    • Geo-location = public peer endpoints joined to the validator directory, enriched with a GeoIP lookup. ASN/provider is reliable; city is approximate.
    • RTT from JP = ICMP echo from our Prague server (5 packets/host), re-measured hourly through the epoch; the published figure is the average of all rounds so far, as a stake-weighted median over reachable hosts. Some hosts block ICMP and are excluded from the latency figure only, not from stake.
    • Continents = coarse buckets (EU / NA / APAC / Other) by country code, for a quick decentralization read.
    • 33% BFT line = the share of stake above which a single correlated failure starts to threaten liveness; shown against the largest single provider (one correlated-failure domain). We also note how few providers it takes to reach 1/3 of stake, as a concentration-depth read.
    • Trends = one snapshot of these same aggregates is stored per day; the trend charts and 7d / 30d deltas are computed from that rolling history. There is no back-fill, so history begins the day this feature went live.
    • Aggregates only = this page publishes continent / country / ASN aggregates only. Per-validator IP, name, and city mappings are kept private on purpose.
    • Not a criticism of any operator = mainstream hosts are the rational default. The goal is to make the ASN-concentration number visible next to the country numbers.
